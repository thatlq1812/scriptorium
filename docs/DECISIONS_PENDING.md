10. **(2026-07-29) Consuming-agent tool-composability guidance gap.** Owner reported real testing on a friend's machine: the consuming agent under-used a Scriptorium skill bundle, applying a generic "only call tools when necessary" instinct from its own system prompt even though several skills in the bundle are designed to chain for one task. Fixed at the distribution layer (the point where this actually reaches a consuming agent): `skill-exporter` v0.2.2 adds a "Note for the agent using this bundle" section to every generated `MANIFEST.md`, explicitly stating that chained/dependent skills are meant to be used together and a minimize-tool-calls heuristic shouldn't be applied against a real pipeline. Verified real against an actual multi-dependency export. Not fixed (deliberately, scope boundary): Scriptorium cannot edit a downstream user's own `AGENTS.md`/`CLAUDE.md`/system prompt — the fix lives in what Scriptorium *hands* the consuming agent (the manifest), not in rewriting that agent's own configuration, which is outside this project's control and would be a different kind of overreach.
