## v0.2.0 hardening round (2026-07-26)

The 5 harvested skills were re-tested adversarially — running each script against inputs it was never shown during authoring (unresolvable identifiers, non-UTF-8 files, duplicate headers, `inf` cells, 1200-level JSON nesting, unfilled templates, lowercase headings, domain vocabulary that collides with the tone lexicon). Every defect below was reproduced first, then fixed, then re-verified. Full per-skill detail lives in each `SKILL.md`'s `metadata.changelog_0_2_0`.

Three were the kind that make a skill worse than having no skill at all — the tool's stated guarantee was false in exactly the case the guarantee exists for:

1. **`citation-management` fabricated citations.** An unresolvable PMID returned `@article{Unknownnd, title={Untitled}, author={Unknown}, pmid={99999999}}` and exit 0. The SKILL.md claimed it "fails loudly instead of inventing plausible-looking metadata," and cites `STRATEGY_SPEC.md` §5 (the *Mata v. Avianca* fabricated-case-law precedent) as the reason. Every resolver now validates the record it receives; an unknown identifier writes nothing and exits 1.
2. **`hypothesis-generation` had an ungated generator.** `generate_preregistration_scaffold.py` ran on any record, so a record with `status: "confirmed"`, a single non-rival candidate, a self-contrasting prediction and no accountable human produced a clean-looking preregistration. The invariant "a hypothesis is never confirmed by construction" was enforced only by a validator nothing required. The generator is now gated on it, no bypass flag — matching how `peer-review` already gated its own generator.
3. **`peer-review`'s mandatory intake gate accepted an unfilled template.** Copying `review_intake_template.json`, flipping the 3 booleans, and changing nothing else returned `READY_FOR_LOCAL_REVIEW` — authorization, accountable human, and retention plan all still template placeholders. Placeholders now count as unfilled, and `ai_tool_policy` (which the SKILL.md required but no tool checked) is enforced.

The rest were correctness and robustness: wrong quartile math driving `exploratory-data-analysis`'s headline outlier flag (index-based, no interpolation); 4 uncaught-traceback paths in that same skill (`inf` cell, non-UTF-8 file, deep JSON, oversized CSV field) in a skill whose entire posture is "every value is untrusted"; silent data loss on duplicate CSV headers; JSON missingness undercounted for any key first appearing after record 1; `literature-review` never merging an arXiv preprint with its published record (the most common duplicate shape, corrupting the PRISMA dedup count) and exiting 0 when every source failed; unescaped BibTeX output breaking any LaTeX build on a title containing `&`, `%` or JATS markup; and a tone linter flagging "garbage collection" as abuse while passing an actual personal attack.

**Process note**: all 17 were reachable by running the scripts against hostile input for ~20 minutes. None required reading the source carefully. This is the gap `quality-eval` (stage 4) is supposed to catch and has never run on any skill — the more valuable version of that stage is not "does the skill help vs. baseline," it is "does the skill do what its own SKILL.md says under inputs the author didn't imagine."

**Acted on, same day (owner decision)**: that pass is now built into `quality-eval` v0.2.0 as **Pass A — contract conformance under adversarial input**, with the input classes distilled into `skills/quality-eval/references/adversarial-input-catalog.md` and a fixture generator at `skills/quality-eval/scripts/make_adversarial_fixtures.py`. **Running stage 4 on any skill remains deliberately deferred** — the owner's call was to build the instrument now and not start evaluating yet. Do not run stage 4 in a later session without asking.

The instrument was exercised against the round's own output rather than left as prose: 21 fixtures generated, all run through the hardened `exploratory-data-analysis` with zero tracebacks — and it immediately found an 18th defect, this one in this session's own fix. The `inf` crash had been closed for the token form (`inf`, `-Infinity`) but not the value form: a literal like `1e400` passes any numeric pattern, overflows to infinity on `float()`, and crashed the identical `statistics.pstdev` call. Fixed and re-verified, along with typing an all-non-finite column as `all_non_finite` instead of mislabeling it text. The lesson is the same one the catalog closes with, now demonstrated on the fixer rather than the original author: a fix verified against the case you thought of is not a fix.
